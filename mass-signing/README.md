# Массовое подписание — прототип

Кликабельный прототип сценария массового подписания документов в ЭДО Точки,
собранный по макетам **«🚧 Массовое подписание (после ю-тестов)»**
([Figma, страница `5317:24012`](https://www.figma.com/design/cIVJfWTs4Opft0BvuYe7Rl/?node-id=5317-24012)).

Самодостаточное Vite-приложение на React + TypeScript. UI-кит подключается
из соседней папки `design-system/`.

## Запуск

```bash
npm install
npm run dev
```

Импорт компонентов кита — `import { Button } from '@ds'`, иконок — `from '@ds/icons'`.

## Сценарий

```
Список документов ──► Куда отправить ──► Как подписать ──┬─► Электронной подписью ─► Результат
                      (можно пропустить)   (можно        └─► СМС-кодом ─► Код №1…№N ─► Результат
                                            пропустить)
```

### 1. Список документов (`screens/DocumentListScreen.tsx`)

12 документов из макета. Статус документа — тегом в колонке «Документ»,
в колонках «НДС» и «1С» — залитые индикаторы, дальше PDF и меню.

Как только выбран хотя бы один документ, снизу появляется липкий футер
«Выбрано N документов» с кнопками «Отправить в 1С» и «Подписать
и отправить». Если среди выбранного нет ни одного документа со статусом
«Ждёт вашей подписи», подпись футера сразу краснеет: «Выберите документ,
который нужно подписать». Ошибки внутри документов на эту проверку
не влияют — их разбирают на шаге «Как подписать».

«Отправить в 1С» — заглушка: показывает уведомление и ничего не меняет.

### 2. Куда отправить документы (`screens/SendStep.tsx`)

Шаг показывается, только если хотя бы у одного контрагента партии нет системы
ЭДО. Если система известна для всех — сразу открывается «Как подписать».

- **«Выберите ЭДО контрагента»** — контрагенты, с которыми обмениваются впервые.
  Клик по строке открывает шторку выбора оператора (`OperatorPickerDrawer`);
  после сохранения контрагент переезжает в нижнюю группу, сверху появляется
  зелёная плашка «Контрагент изменён». Когда ЭДО выбрали последнему
  контрагенту, шаг сразу сменяется на «Как подписать» — делать на нём
  больше нечего.
- **«ЭДО уже выбран»** — сворачиваемая группа; в строке под названием
  контрагента ИНН и система ЭДО.
- При первом входе к первому контрагенту без ЭДО прилипает тёмная подсказка
  «Нажмите на контрагента и выберите нужный ЭДО — запомним ваш выбор»
  с кнопкой «Понятно» — показывается один раз за сессию.
- «Продолжить» с незаполненными операторами подсвечивает строки красным
  «Выберите систему ЭДО».

### 3. Как подписать (`screens/SignStep.tsx`)

Два способа подписания и правая колонка со счётчиком «Подписано N из M».
Три состояния экрана:

- **есть НЭП и КЭП** — оба способа доступны;
- **есть ошибки, НЭП и КЭП** — то же самое: подписанные и документы
  с ошибками видно только внутри способа, на самом экране их нет;
- **только КЭП** — «СМС-кодом» гаснет с подписью «Нет документов
  на подпись НЭП».

Когда доступна только КЭП, экран показывают, лишь если перед ним был шаг
«Куда отправить». Если шагов не было вовсе, мастер не открывается совсем:
шторка КЭП ложится поверх списка документов, и её закрытие заканчивает
сценарий — подписанное сохраняется.

Каждый способ — одна шторка (`SignMethodDrawer`) с навигаторами по спискам:

| | Электронной подписью | СМС-кодом |
|---|---|---|
| Полномочия | доверенность и сертификат | — |
| «На подпись» | N из M будут подписаны КЭП | N из M будут подписаны НЭП |
| «Подписать электронной подписью» | — | N из M только токен-флешкой, КЭП |
| «Не получится подписать» | N из M уже подписаны или содержат ошибки | то же |

Навигатор «Подписать электронной подписью» скрыт, если всё можно подписать
НЭП; «Не получится подписать» — если нет подписанных и документов с ошибками.

За «На подпись» лежит список с чекбоксами и «Сбросить» в шапке, «Сохранить»
возвращает в шторку способа. «Подписать» у КЭП сразу показывает результат,
у СМС — просит пятизначный код на каждый документ. Код в прототипе любой.

Когда подписаны все доступные документы, «Готово» в окне результата
возвращает к списку. «Выйти на главную ЭДО» прерывает сценарий с
подтверждением: подписанное сохраняется, остальное придётся выбрать заново.

### «Не получится подписать» (`CannotSignDrawer`, `DocumentCardDrawer`)

Один список в порядке документов: причину, которую можно исправить, красят
в красный, остальные — серым. Клик по строке открывает карточку документа:

- у исправимой ошибки в футере «Редактировать» → после «редактирования»
  ошибка снимается и кнопка меняется на «Подписать и отправить»;
- у неисправимой — «Удалить», документ уходит из партии.

## Логика в данных

Всё поведение выводится из `data.ts` и `signing.ts`, а не зашито в экраны.

| Правило | Где |
|---|---|
| Подписать можно только документ со статусом «Ждёт вашей подписи»; «Подписано» и «Ожидает оплаты» попадают в «Не нужно подписывать» | `signing.ts`, `blockOf` |
| НЭП не подходит для УПД, счетов-фактур, УКД, КСФ (`isKepOnlyType`) и для документов контрагентам не в ЭДО Точки | `signing.ts`, `supportsMethod` |
| Шаг «Куда отправить» пропускается, когда у всех контрагентов партии есть система ЭДО | `App.tsx`, `handleStartSigning` |
| Когда ЭДО выбрали последнему контрагенту, шаг закрывается сам — без «Продолжить» | `App.tsx`, `handleSaveOperator` |
| Мастер не открывается, когда доступна только КЭП и не было шага «Куда отправить» — шторка ложится поверх списка | `App.tsx`, `enterSignScreen`, `handleDrawerClose` |
| Шторка способа пропускается у руководителя с единственной КЭП и без доверенностей — документы подписываются сразу | `App.tsx`, `NEEDS_METHOD_DRAWER` |

Ошибки заданы прямо в фикстурах: Договор №14 — «К исправлению» (нет в ЕГРЮЛ),
Счёт №88 — «Не нужно подписывать» (бизнес ликвидирован). Формулировки взяты
из фрейма «Варианты ошибок» (`5440:103264`). Сертификаты и доверенности —
из фрейма «Параметры подписания» (`5422:62672`).

## Чего нет

- **Адаптив.** Прототип рассчитан на десктоп; 375px-версии из макетов ещё не
  собраны. Подписание КЭП в адаптиве и не показывают — так в макетах.
- **Ошибка подписания.** Экран «Документы не подписаны» (проблема с КриптоПро)
  нарисован, но в прототипе подписание всегда успешно — триггера в макетах нет.
- **Ошибки запросов.** Красные алерты в шторке выбора оператора помечены
  в макетах как спецификация для разработчика, в прототипе не воспроизводятся.
- **Редактирование документа.** По макетам «Редактировать» открывает штатный
  сценарий правки; здесь он сведён к снятию ошибки.
- **Дровер выбора тарифа** для клиентов на Базовом ЭДО.
- **«Посмотреть полномочия»** в карточке доверенности — ссылка есть,
  но экрана за ней в макетах нет.
- **МЧД как признак сотрудника.** По макетам сотруднику с МЧД доступна
  только КЭП; в прототипе доверенности есть у руководителя, поэтому
  правило не влияет на флоу.

## Расхождения с макетами

- В макетах «Не получится подписать 2 из 12». В прототипе таких документов
  четыре: Договор №14 и Счёт №88 с ошибками плюс УПД №63 и Счёт №92,
  которые не ждут подписи.
- На «Точке входа» в макетах счётчик показывает «0 из 12», а на экране
  результата — «8 из 10». В прототипе знаменатель везде один: сколько
  документов вообще можно подписать.
- «Не получится подписать» нарисован дважды: в секции «Как подписать»
  плоским списком, в секции «Не получится исправить» — с заголовками
  «Нужны правки» и «Не подписать». В прототипе взят плоский список,
  он новее.
- В шторке «На подпись» для СМС макет не рисует строку с общим чекбоксом,
  а для КЭП рисует. В прототипе она есть в обеих — иначе после «Сбросить»
  нечем вернуть выбор.
- Список кита позиционируется один раз при открытии, поэтому клик по полю
  в первые 400 мс, пока шторка выезжает, уводит выпадашку за край экрана.
- Заголовки результата в макетах написаны как «Документ подписаны!» и
  «Документ не подписаны» — в прототипе они согласованы по числу,
  вместе с подписью «Контрагенты увидят их в своих ЭДО».
- В подписи уведомления «N из M документов» существительное всегда
  в родительном множественного, как в макете с 12 документами.
